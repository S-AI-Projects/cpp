## File Role Map

All paths are relative to `exercises/practice/minesweeper/`.

## Metadata Validation

### How the Runner Finds Files

1. **Config resolution**: The runner reads `exercises/practice/minesweeper/.meta/config.json`
2. **Path resolution**: Each declared file path is resolved relative to the exercise directory
3. **File existence**: The runner verifies each declared file exists at the expected location

### Declared Files (from config.json)

```json
{
  "files": {
    "solution": ["minesweeper.cpp", "minesweeper.h"],
    "test": ["minesweeper_test.cpp"],
    "example": [".meta/example.cpp", ".meta/example.h"]
  }
}
```

### Validation Rules

- All paths must be relative to the exercise directory
- No parent directory traversal (`..`) allowed
- All declared files must exist
- Solution files must be the learner stubs (not the reference)
- Test files must be the test cases
- Example files must be the reference implementation

## Reproducible Validation

```bash
python3 work/R20-T038/check.py
```

This check:
1. Parses `config.json` and resolves all file paths
2. Verifies all declared files exist
3. Rejects parent traversal and missing files
4. Builds the exercise with the reference implementation
5. Runs all 12 test cases (no rows, no columns, no mines, etc.)
