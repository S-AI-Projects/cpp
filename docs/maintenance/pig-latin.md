# Pig Latin (`exercises/practice/pig-latin`) — Test-Generation & Preparation Path

## Overview

For `pig-latin`, there is **no per-exercise test generator or Jinja template** (`exercises/practice/knapsack/.meta/create_tests.py` is the only per-exercise test generator in this track). Instead, the exercise follows a two-stage track workflow:

| Artifact | Path | Maintained / Generated By | Role |
| :--- | :--- | :--- | :--- |
| Canonical selection manifest | `exercises/practice/pig-latin/.meta/tests.toml` | **Generated / synced** via `bin/configlet sync` (`.github/workflows/run-configlet-sync.yml`) | Records the `23` included canonical UUIDs (`0` excluded). |
| Catch2 test suite | `exercises/practice/pig-latin/pig_latin_test.cpp` | **Hand-maintained** | Defines `23` `TEST_CASE` blocks, each tagged with its exact `[<uuid>]` from `.meta/tests.toml`. |
| Reference implementation | `exercises/practice/pig-latin/.meta/example.h`, `.meta/example.cpp` | **Hand-maintained** | Reference implementation of `pig_latin::translate`. |
| Learner stub | `exercises/practice/pig-latin/pig_latin.h`, `pig_latin.cpp` | **Hand-maintained** | Unsolved learner placeholders (`// TODO: add your solution here`). |
| Prepared build tree | `build_exercises/practice/pig-latin/` | **Generated** at configure time by root `CMakeLists.txt` (`build_fixup`) | Copies exercise files and renames `.meta/example.*` -> `pig_latin.h` / `pig_latin.cpp`. |

At compile time, `-DEXERCISM_RUN_ALL_TESTS=ON` (default `ON` in root `CMakeLists.txt:29`) un-skips cases 2–23 sitting inside `#if defined(EXERCISM_RUN_ALL_TESTS)` (`pig_latin_test.cpp:12-111`) without rewriting source files. Neither `pig_latin_test.cpp` nor `build_fixup()` embeds timestamps, so the normalization step between independent preparations is the **identity function**.

## Exact Reproduction Commands

### 1. Reproducible Two-Copy Preparation Check (Reusable Tool)

Run from the repository root:

```bash
python3 tools/course_checks/r20-t042.py --exercise pig-latin
```

This creates two independent clean clones via `git archive org/main | tar -x`, runs root CMake preparation (`cmake -S . -B b`), compares SHA-256 digests of `build_exercises/practice/pig-latin/pig_latin_test.cpp`, `pig_latin.cpp`, and `pig_latin.h`, compiles `--target pig-latin`, compares `--list-test-names-only` output (`23` cases), and verifies the exact bijection between the `23` included `.meta/tests.toml` UUIDs and the `23` `[uuid]` tags in `pig_latin_test.cpp`.

*(Note: Root `CMakeLists.txt` compiles all exercises. When Boost `date_time` is absent on the host, `.github/workflows/ci.yml:71-73` removes `exercises/practice/gigasecond` and `exercises/practice/meetup` in the temporary copy before running `cmake -S . -B b`.)*

### 2. Full R20-T042 Exercise Verification & Negative Controls

```bash
python3 work/R20-T042/check.py
```

Expected final line:

```text

```

### 3. Single-Exercise Isolated Build & XML Execution (in a Temporary Copy)

```bash
cmake -S . -B build -DEXERCISM_RUN_ALL_TESTS=ON
cmake --build build
./build/pig-latin -r xml -o results.xml
```

### 4. Upstream Canonical Sync Check (`configlet`)

```bash
./bin/fetch-configlet
./bin/configlet sync --tests --exercise pig-latin
```

Running `configlet 4.0.3` (without `--update`) in an isolated archive copy of `org/main` (`8d139cb04c7463722ae1f233099cc0bd39a71092`) confirmed that all `23` entries in `exercises/practice/pig-latin/.meta/tests.toml` match `pig_latin_test.cpp` (`23/23` exact UUID bijection) and exited `1` warning that upstream `problem-specifications` added `2` newer `"a whole phrase"` cases (`44616581-5ce3-4a81-82d0-40c7ab13d2d0`, `44616581-5ce3-4a81-82d0-40c7ab13d2d1`) after the pinned commit.
